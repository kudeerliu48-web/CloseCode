# 代码审查技能

## 描述
系统化审查代码质量，从功能正确性、性能、安全、可维护性等多个维度找出问题并给出改进建议。

## 审查流程

### 1. 理解上下文
- 阅读相关需求和设计文档
- 了解代码的业务目的
- 查看相关的现有代码

### 2. 功能正确性审查
- [ ] 逻辑是否正确实现了需求
- [ ] 边界条件是否都考虑到（空值、零、负数、最大值等）
- [ ] 错误处理是否完整（try-catch、错误返回）
- [ ] 并发场景是否安全（竞态条件、死锁）

### 3. 代码质量审查
- [ ] 命名是否清晰表达意图（变量、函数、类名）
- [ ] 函数是否过长（建议不超过50行）
- [ ] 是否有重复代码（DRY原则）
- [ ] 注释是否必要且准确（代码应自解释，复杂逻辑才需要注释）
- [ ] 是否符合项目代码规范（缩进、命名风格、文件结构）

### 4. 性能问题审查
- [ ] 数据库查询是否高效（N+1问题、缺少索引、全表扫描）
- [ ] 是否有不必要的循环嵌套
- [ ] 大数据量处理是否合理（分页、流式处理）
- [ ] 是否有内存泄漏风险（事件监听未清理、闭包引用）
- [ ] API调用是否可以批量/缓存

### 5. 安全问题审查
- [ ] SQL注入风险（是否使用参数化查询）
- [ ] XSS风险（用户输入是否转义）
- [ ] CSRF保护（敏感操作是否验证token）
- [ ] 权限校验（是否验证用户权限）
- [ ] 敏感数据处理（密码加密、token不记录日志）
- [ ] 输入验证（类型、长度、格式）

### 6. 可维护性审查
- [ ] 模块职责是否单一清晰
- [ ] 依赖关系是否合理（避免循环依赖）
- [ ] 是否便于测试（依赖可mock）
- [ ] 配置是否外部化（不硬编码）
- [ ] 日志是否充分（关键操作、错误场景）

## 审查输出格式

为每个问题输出：

```
文件: path/to/file.js
行号: 123
严重程度: Critical / Major / Minor
类型: [功能/性能/安全/质量/维护性]
问题描述: 具体说明问题是什么
影响: 可能导致什么后果
建议: 如何修改（给出具体代码示例）
```

## 严重程度定义

- **Critical**: 必须修改，否则会导致功能错误、安全漏洞或严重性能问题
- **Major**: 强烈建议修改，存在潜在风险或明显的代码质量问题
- **Minor**: 可选优化，改进后会更好但不影响功能

## 审查原则

1. **客观具体**: 指出具体问题和位置，不说模糊的"写得不好"
2. **建设性**: 不只批评，给出改进方案
3. **优先级**: 先关注Critical问题，再看Major和Minor
4. **认可优点**: 好的设计和实现也要指出
5. **尊重规范**: 遵循项目现有的代码风格和架构决策

## 常见问题清单

### 前端
- 未处理异步错误
- 未清理定时器/事件监听
- 直接操作DOM而不是通过框架
- 未做防抖节流
- 敏感信息暴露在前端代码

### 后端
- SQL拼接而不是参数化查询
- 未验证用户权限
- 密码明文存储
- 未处理事务
- 未做并发控制

### 通用
- 魔法数字（硬编码常量）
- 过长的函数
- 深层嵌套
- 全局变量污染
- 未处理的异常

## 使用示例

加载技能后，按以下步骤执行：

1. 读取要审查的代码文件
2. 按6个维度逐项检查
3. 记录发现的问题
4. 按严重程度排序
5. 输出结构化的审查报告
